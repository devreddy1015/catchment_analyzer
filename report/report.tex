%=======================================================================
\section{What it does}
%=======================================================================

Upload a contour map as KML or KMZ. The service rebuilds the terrain surface,
routes water across it, picks a pond site, and returns the catchment draining to
that site as JSON.

Nothing is tied to the sample map. Extent, elevation range, contour interval,
grid size and every normalisation range are read from whatever file arrives. The
sample was used to test the code, not to tune it.

\begin{table}[H]
\centering\small
\begin{tabular}{@{}p{0.44\textwidth}p{0.48\textwidth}@{}}
\toprule
\textbf{Requirement} & \textbf{Where} \\
\midrule
\texttt{POST /analyzeContour} or \texttt{/findCatchment} & Both; the second is an alias (\S\ref{sec:api}) \\
Accept contour map as upload & \texttt{multipart/form-data}, KML + KMZ \\
Analyse terrain & \S\ref{sec:approach}, stages 1--4 \\
Identify pond location & \S\ref{sec:approach}, stage 6 \\

Demonstrate on sample map & \S\ref{sec:demo} \\
No hard-coded results & \S\ref{sec:general} \\

%=======================================================================
\section{How the catchment is found}
\label{sec:approach}
%=======================================================================

This is the standard raster-hydrology chain, built on published algorithms
rather than invented rules. Pseudocode below; the code is in the repository.

\subsection{Stage 1 --- Read the contours}

A KMZ is a zip; the \texttt{.kml} inside is extracted first. Elevation comes from
whichever place the file actually puts it, since files in the wild differ.

\begin{algobox}{Algorithm 1 --- Read contours}
\begin{lstlisting}[style=pseudostyle]
function read_contours(bytes):
    if bytes is a zip then bytes <- extract largest .kml member
    foreach placemark in parse_xml(bytes):
        coords <- parse_coordinates(placemark)
        z <- first available of: coordinate altitude,
                                 <ExtendedData> elevation,
                                 numeric <name>
        if z exists and coords has >= 2 points then keep ContourLine(coords, z)

    drop levels isolated from the series     // spot heights, stray labels
    assert >= 3 lines and >= 2 distinct levels

    bounds   <- min/max of all vertices      // all DERIVED, never assumed
    interval <- median gap between levels
    return ContourSet(lines, bounds, levels, interval)
\end{lstlisting}
\end{algobox}

\subsection{Stage 2 --- Build a surface}

Contours are scattered points carrying a $z$ value. A Delaunay-based linear
interpolation turns them into a grid, with nearest-neighbour fill outside the
hull and light smoothing to remove triangulation facets.

\begin{algobox}{Algorithm 2 --- Interpolate onto a grid}
\begin{lstlisting}[style=pseudostyle]
function build_grid(contours, resolution = 160):
    (s, w, n, e) <- contours.bounds, padded slightly

    // Cells are kept SQUARE IN METRES -- D8 assumes it.
    if width_m >= height_m then
        cols <- resolution;  rows <- resolution * height_m / width_m
    else
        rows <- resolution;  cols <- resolution * width_m / height_m

    targets <- regular lon/lat mesh (rows x cols), north-up
    values  <- LinearNDInterpolator(vertices, elevations)(targets)
    values[NaN] <- NearestNDInterpolator(...)      // outside the hull
    surface <- uniform_filter(values)

    return ElevationGrid(surface, bounds, cell_size_m, interval)
\end{lstlisting}
\end{algobox}

\subsection{Stage 3 --- Fill the sinks}

Routing on a raw surface strands water in every hollow. Priority-flood filling
raises each pit to its spill level. The fill depth is not waste: it \emph{is} the
depth of the hollow, which stage 6 uses as evidence of natural storage.

\begin{algobox}{Algorithm 3 --- Priority-flood sink fill}
\begin{lstlisting}[style=pseudostyle]
function fill_sinks(z, epsilon = 0):
    filled <- copy of z
    queue  <- min-heap of ALL BOUNDARY cells, keyed by elevation

    while queue not empty:
        (level, r, c) <- pop lowest
        foreach unvisited 8-neighbour (nr, nc):
            mark visited
            // no cell can sit lower than the lowest rim reaching it
            filled[nr, nc] <- max(filled[nr, nc], level + epsilon)
            push (filled[nr, nc], nr, nc)
    return filled

depression_depth(z)    = max(0, fill_sinks(z, 0) - z)
conditioned_surface(z) = fill_sinks(z, 1e-4)   // tilt flats so flow is defined
\end{lstlisting}
\end{algobox}

The $\epsilon$ tilt matters: a filled pit is a flat lake where no cell has a
downhill neighbour, so flow would be undefined across it.

\subsection{Stage 4 --- Route the water}

\begin{algobox}{Algorithm 4 --- D8 direction and accumulation}
\begin{lstlisting}[style=pseudostyle]
function flow_direction(z, cell_size_m):
    // each cell drains to its steepest downhill neighbour of eight
    padded <- z padded with +infinity          // off-grid can never win
    foreach k, (dr, dc) in the 8 offsets:
        slope <- (z - padded shifted by (dr,dc)) / (cell_size_m * dist[k])
        direction <- where(slope > best, k, direction)
    return direction                            // -1 marks a pit

function flow_accumulation(z, direction):
    // water only moves downhill, so highest-to-lowest means a cell's
    // total is final before it is passed on -- one linear pass
    accumulation <- ones
    foreach cell sorted by z descending:
        d <- downstream neighbour
        if d exists then accumulation[d] += accumulation[cell]
    return accumulation
\end{lstlisting}
\end{algobox}

\subsection{Stage 5 --- What the ground already is}

Before proposing anything, the map is split by \emph{upstream area}, so the rule
transfers to other terrain unchanged.

\begin{table}[H]
\centering\small
\begin{tabular}{@{}lll@{}}
\toprule
\textbf{Class} & \textbf{Test} & \textbf{Result} \\
\midrule
Pond ground  & upstream $\le 25$\,ha           & pond proposed \\
Nala         & $25 < $ upstream $\le 100$\,ha  & bund / percolation tank \\
River        & upstream $> 100$\,ha            & nothing proposed \\
Floodplain   & within 40\,m, HAND $< 3$\,m     & nothing proposed \\
Still water  & flat pooled area $\ge 2$\,ha    & nothing proposed \\
\bottomrule
\end{tabular}
\end{table}

Past roughly 25\,ha a storm delivers more than a farm pond can hold, and the
problem becomes a spillway rather than an embankment. Reporting that as a
different structure is more useful than silently recommending the wrong one.

\subsection{Stage 6 --- Choose the site}

Four layers, each normalised against the range present \emph{in the uploaded
map} --- so the score is relative to that terrain, never to a fixed constant.

\begin{equation}
n(x) = \frac{x - \min x}{\max x - \min x},
\qquad
S = 100 \cdot \frac{\sum_i w_i L_i}{\sum_i w_i}
\end{equation}

\begin{table}[H]
\centering\small
\begin{tabular}{@{}llr@{}}
\toprule
\textbf{Layer} & \textbf{Value} & \textbf{Weight} \\
\midrule
Depression & $n(\text{fill depth})$ & 0.30 \\
Catchment  & $n(\log(1+A))$ & 0.30 \\
Slope      & $n\!\left(1/(1+\theta/8^{\circ})\right)$ & 0.25 \\
Elevation  & $n(-z)$ & 0.15 \\
\bottomrule
\end{tabular}
\end{table}

The logarithm on accumulation matters --- raw upstream counts span orders of
magnitude, and without it one trunk channel saturates the layer and flattens
every real difference elsewhere.

\begin{algobox}{Algorithm 5 --- Score, filter, rank}
\begin{lstlisting}[style=pseudostyle]
function select_sites(grid, accumulation, depths, max_sites):
    score <- 100 * weighted_sum(four normalised layers) / sum(weights)

    blocked <- river or floodplain or still_water or outer edge ring
    // busy channel with no hollow the source could measure = interpolation
    holds   <- max(0.30, grid.vertical_resolution_m)
    blocked <- blocked or (accumulation >= percentile(accumulation, 95)
                           and depths < holds)

    foreach cell in unblocked cells sorted by score descending:
        if enough sites then break
        if too close to an accepted site then continue

        storage <- natural_storage(grid, depths, cell)
        inflow  <- upstream_area * 0.4 * 50mm       // one ordinary storm
        if inflow > storage.volume then
            reclassify as channel structure (bund + waste weir)
        else
            accept as PondSite
\end{lstlisting}
\end{algobox}

Storage is measured, not assumed from a design depth. The sink fill already
gives the spill elevation, so the pond is grown out to that real rim:

\begin{algobox}{Algorithm 6 --- Storage by flood fill to the rim}
\begin{lstlisting}[style=pseudostyle]
function natural_storage(grid, depths, cell):
    if depths[cell] <= 0 then return zero      // no hollow; must be dug
    spill <- grid.z[cell] + depths[cell]

    flood outwards from cell over neighbours with z < spill:
        head_sum <- head_sum + (spill - z of each flooded cell)

    return { depth, spill, area = count * cell_area,
             volume = head_sum * cell_area }
\end{lstlisting}
\end{algobox}

\subsection{Stage 7 --- Delineate the catchment}

The catchment is exactly the set of cells whose flow pointers lead to the site
--- found by walking the D8 network upstream from it.

\begin{algobox}{Algorithm 7 --- Delineate}
\begin{lstlisting}[style=pseudostyle]
function delineate(grid, direction, outlet):
    contributors <- invert(direction)     // downstream -> list of upstream
    cells <- {outlet};  queue <- [outlet]
    while queue not empty:
        foreach up in contributors[pop queue] not already in cells:
            add up to cells and queue

    area      <- count(cells) * cell_area
    polygon   <- union of cell squares
    flow_path <- longest upstream chain, in metres
    gradient  <- (max_z - min_z) / flow_path
    return Catchment(area, polygon, flow_path, gradient, relief, slope)
\end{lstlisting}
\end{algobox}

\subsection{Stage 8 --- Yield}

\begin{equation}
V = P \cdot A \cdot C
\qquad\qquad
t_c = 0.0195\, L^{0.77} S^{-0.385}
\end{equation}

$P$ rainfall (mm), $A$ area (m\textsuperscript{2}), $C$ runoff coefficient
(default 0.4), $L$ longest flow path (m), $S$ gradient. With no rainfall given,
the response reports yield per millimetre so local rainfall can be applied later.

\section{Extending it, and what it cannot do}
%=======================================================================

\textbf{Built to extend.} \texttt{build\_grid} is shared by the contour path and
the DEM path, so a grid from a raster has the same geometry as one from
contours and every later stage is source-agnostic --- adding GeoTIFF input means
writing one reader. Thresholds are in hectares and metres, so no retuning for a
new district. Resolution is a request parameter. The core imports nothing from
FastAPI.

\textbf{Limits, stated plainly.} Interpolation cannot recover features finer
than the contour interval, so hollows under 1\,m are indistinguishable from
smoothing artefacts on this map. About 7.6\,\% of the grid lies outside the
contour hull and is extrapolated, which is why the outer ring is excluded from
siting. Catchments are clipped by the map extent --- flow from beyond it is not
counted, and the response warns when a catchment touches the boundary. The
Rational method suits small catchments, not basin-scale routing.
